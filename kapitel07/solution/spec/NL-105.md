# Spezifikation NL-105: Bestellung stornieren

Stand: 20.10.2026, freigegeben von Miriam Kessler

## Kontext
Storno geht heute nur über den Kundenservice. Belege:
orders.py:42-47 TRANSITIONS kennt keinen Storno-Status,
api.py hat keine Storno-Route, inventory.release() gibt
reservierten Bestand frei (inventory.py:84-93).

## Verhalten
S1 Given eine Bestellung im Status new oder paid ohne Label
   When POST /orders/{id}/cancel mit E-Mail der Bestellung
   Then 200, Status cancelled, Reservierung freigegeben
S2 Given ein Versandlabel existiert
   When POST /orders/{id}/cancel
   Then 409, Status unverändert
S3 Given Status shipped, payment_failed oder cancelled
   When POST /orders/{id}/cancel
   Then 409, Status unverändert
S4 Given eine E-Mail, die nicht zur Bestellung passt
   When POST /orders/{id}/cancel
   Then 403, Status unverändert
S5 Given eine unbekannte Bestellnummer
   When POST /orders/{id}/cancel
   Then 404
S6 Jeder Storno steht in GET /orders/{id}/history

## Nicht-Ziele
Teilstorno, Erstattung, Löschen eines Labels, Anmeldung.
